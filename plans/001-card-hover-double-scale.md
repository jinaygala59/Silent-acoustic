# 001 — Collapse the card's double hover scale into one

- **Status**: DONE (executed at b58af61; verified in-browser)
- **Commit**: b58af61
- **Severity**: HIGH
- **Category**: Cohesion & tokens / Easing & duration
- **Estimated scope**: 2 files, 3 declarations

## Problem

A product card scales **twice** on hover. Two rules in two different stylesheets
each scale a different element in the same nested chain, and neither knows about
the other.

The markup (generated by `src/build.js:171`, do not edit) is:

```html
<a class="card">
  <div class="card-surface surface s-…">
    <img src="…-card.webp">
  </div>
  <div class="card-body">…</div>
</a>
```

The outer frame scales:

```css
/* assets/css/motion.css:422-423 — current */
.card-surface, .fam-surface { transition: transform 600ms var(--m-out); }
a.card:hover .card-surface, .fam:hover .fam-surface { transform: scale(1.03); }
```

The image inside it scales too:

```css
/* assets/css/site.css:596-598 — current */
a.card:hover > .card-surface > img,
.gal-item:hover > .gal-surface > img { transform: scale(1.035); }
.card-surface > img, .gal-surface > img { transition: transform 520ms var(--ease); }
```

CSS transforms compound down the tree, so hovering a card actually scales the
photograph by **1.03 × 1.035 = 1.0661** — more than double what either rule reads
as on its own. Worse, the two halves disagree on both timing inputs:

| | duration | curve |
|---|---|---|
| `.card-surface` | 600ms | `--m-out` = `cubic-bezier(0.4, 0, 0.2, 1)` |
| `.card-surface > img` | 520ms | `--ease` = `cubic-bezier(0.22, 1, 0.36, 1)` |

The image finishes moving **80ms before its own frame does**, on a different
acceleration profile. In slow motion the photo visibly slides inside the frame
and then the frame catches up.

Two further problems: 600ms and 520ms are both far over the budget for hover
feedback (UI motion stays under 300ms), and the comment above the motion.css
rule promises the card "lifts its own surface **a touch**", which 1.066 is not.

This is the site's most repeated interaction — 19 product cards plus every
category grid.

**One thing that is NOT broken and must be preserved:** the second selector in
the site.css:596 list, `.gal-item:hover > .gal-surface > img`, is *not* doubled.
Nothing scales `.gal-surface` itself, so gallery items have exactly one scale
and are correct today. Only the `a.card` half of that selector list is the bug.

## Target

One scale, on the frame, at the duration and curve the repo already uses for
hover lifts elsewhere.

```css
/* assets/css/motion.css:422-423 — target */
.card-surface, .fam-surface { transition: transform 240ms var(--ease); }
a.card:hover .card-surface, .fam:hover .fam-surface { transform: scale(1.03); }
```

```css
/* assets/css/site.css:596-598 — target */
.gal-item:hover > .gal-surface > img { transform: scale(1.035); }
.gal-surface > img { transition: transform 240ms var(--ease); }
```

Net effect: cards scale 1.03 once over 240ms on `--ease`; gallery items keep
their single 1.035 scale, brought onto the same 240ms/`--ease` timing for
consistency.

## Repo conventions to follow

- Easing tokens: `--ease` is defined at `assets/css/site.css:175` as
  `cubic-bezier(0.22, 1, 0.36, 1)`. `--m-in` (`assets/css/motion.css:23`) is an
  alias of it. `--m-out` (`assets/css/motion.css:24`) is
  `cubic-bezier(0.4, 0, 0.2, 1)`. **Do not define a new curve** — use `--ease`.
- 240ms is not invented: it is already the repo's hover-transition duration.
  Exemplars to imitate — `assets/css/site.css:964` (`.sector`) and
  `assets/css/motion.css:286` (`.fam`), both `transition: … transform 240ms …`.
- Durations are written inline as literals in this codebase (there are unused
  `--m-fast` / `--m-mid` tokens at `assets/css/motion.css:26-27` — **leave them
  alone**, consolidating them is a separate, unplanned finding).

   ```

3. In `assets/css/site.css`, line 598, drop the now-unused `.card-surface > img`

   ```

4. Leave the comment block at `assets/css/motion.css:420-421` in place — it is
   now accurate for the first time.
